Vox call — target state, distributed topology

Laptop hosts the audio hardware and voxd. The dev-box hosts Claude Code sessions, mcp-proxy, vox call, and the per-turn bare subprocess. Only text and events cross the WAN — no PCM. External API traffic egresses from whichever machine actually needs it (ElevenLabs from the laptop, Anthropic from the dev-box).

What changes vs today

  • winsMic capture, TurnDetector, and STT move into voxd. No PCM crosses the WAN. Bandwidth of a call = a few small JSON messages per turn.
  • winsMic-echo gate is signal-based now — voxd emits playback_ended when mpv actually finishes. The estimated-duration bound goes away.
  • winsBarge-in detection is entirely laptop-local: mic and mpv playback both live inside voxd, so both signals are in-process.
  • winsMCP path collapses to mcp-proxy on the dev-box: ~9 MB per session instead of ~73 MB for a Python vox mcp. Scales linearly with sessions.
  • shape~/.punt-labs/vox/profile.toml is shared by mcp-proxy and vox call. One URL, one bearer, one CA-pin — rotate secrets in one place.
  • shapeURL discovery (Tailscale name, SSH -R, or a reverse tunnel) is a deployment choice, not a code change. mcp-proxy and the streaming client dial whatever the profile says.
  • holdsBare-subprocess-per-turn architecture is unchanged. Fixing the hook cascade (via mcp-proxy --hook across the daemon set) is the next lever — could make --bare unnecessary and restore OAuth support for calls.
